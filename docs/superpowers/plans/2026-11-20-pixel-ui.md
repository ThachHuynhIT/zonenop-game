# Pixel UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox syntax for tracking.

**Goal:** Redesign every game screen in pixel style and fix confirmed client/UI defects.

**Architecture:** Reuse existing shared game-ui APIs with scoped SCSS Modules, original pixel SVG icons and one accessible legacy-dialog adapter. Parallel workers own disjoint files; the controller owns shared foundations and integration.

**Tech Stack:** Next.js 16.4.5, React 19, Sass Modules, Base UI, Vaul, Motion, Vitest, Playwright QA.

**Spec:** docs/superpowers/specs/2026-11-20-pixel-ui-design.md

## Global Constraints

- No game-rule, protocol, backend, database or scoring changes.
- Preserve hidden information, board geometry and original detailed card illustrations.
- SCSS Modules for new layout and visual styling; no new runtime dependencies.
- Read node_modules/next/dist/docs guides before implementation; use m from motion/react under strict LazyMotion.
- Pixel chrome uses the visual contract in the spec; body text remains readable in Vietnamese.
- No production mutations for browser QA and no secrets in artifacts.
- User approved execution and multi-agent coding; proceed through review fixes without additional routine confirmation. No merge.

## Review Focus

1. Delayed account responses must not erase/restore another session.
2. Wake/reconnect during an in-flight join must not create competing active sockets.
3. New chat messages must not steal gameplay focus or scroll a user away from older messages.
4. Keyboard focus must remain inside open dialogs and return on close; hidden cards must not expose their type.
5. Narrow/landscape screens and reduced motion must keep actions reachable and states understandable.
